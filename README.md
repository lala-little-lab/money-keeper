# Money Keeper 本番版1.2（2026-11-05）

## 変更範囲

本番版1.1を基準に、開始日前の未払いカード購入を記録するための日付制限を調整。開始日は残高管理の基準日として保持。履歴の合計・クーポン・暗号化・保存形式11などは変更なし。

## 記録できる条件

- 通常の「支出」で、支払元が設定済みカードに対応し、現金・口座・電子マネー残高を直接動かさないこと。
- 1回払いで、計算された引落日が開始日以降であり、アプリで引落反映済みでないこと。
- 購入日で支出履歴・カテゴリ・特別費に反映し、請求は従来のカード締め日と引落日から計算。購入登録時に口座残高は減らない。
- 開始日前の現金・残高式電子マネー・入金・チャージ・資金移動・やりとり・グループ会計は今回の対象外。開始日前の分割購入や引落日が開始日前の購入も対象外。
- 編集は変更後の支払方法と日付で検証してから元の記録を変更する。引落反映済みの開始前購入は金額等の変更を止め、メモやカテゴリ等だけの編集は許可。

## 初期設定との関係

開始残高は開始日の最初の記録より前の実残高。開始前の未払いカード代には、あとから購入記録として入力する分を除いた残額だけを登録。購入記録と開始時点の未払い額の自動相殺は行わない。重複防止の説明を初期設定画面に追加。

例：請求総額100,000円のうち30,000円を購入記録として残す場合、初期設定の未払い額は70,000円。両方を入力した後、引落画面で合計100,000円を確認。

## 更新方法

MK_prod_03.zipの7ファイルをmoney-keeperに一式アップロード。公開完了後に再読み込みして本番版1.2を確認。テスト版・Miniへはアップロードしない。

初期設定未確定の入力途中データは再読み込みで消えるため、必要な入力値を手元に控えてから更新する。設定や記録が保存済みならバックアップを先に保存し、初期設定や復元をやり直さない。未設定の場合は、更新後に設定引継ぎから再開する。

## 確認結果

仮DOMを用いて実際の新規登録・編集関数を実行。開始日前の2件が設定した締め日から同じ開始後請求に入り、初期未払い残額との合算が一致すること、購入登録・編集で口座残高が動かないこと、支出集計に含まれることを確認。現金への編集が既存記録を変えずに拒否されること、対象外種別・開始前引落・分割・引落済み追加の拒否、引落後メモ編集も確認。JavaScript構文・ZIP内容を確認。利用者端末での本番1.2確認は更新後。
