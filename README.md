# 本番版1.7 更新内容（2026-11-11）

## 口座準備の表示
- 「対象の引落合計」「現在残高」を金額の近くへ寄せます。共通幅196pxの2列配置で項目名の左端・金額の右端をそろえます。狭い画面では画面幅以内に収めます。
- 不足がない場合の「準備OK」「不足見込み：0円」は表示しません。
- 準備期間内に不足がある場合は、従来どおり最初の不足日と期間分の不足額を薄いピンクの枠・ローズ色の金額で表示します。
- 準備期間後だけに不足見込みがある場合は「その先の予定に不足見込みあり」の1行にします。具体的な日付・2か月先までの不足見込み額は口座名横の▼で開いた内訳に表示します。将来額は変動します。
- 口座名横の▼による内訳開閉、合計・残高の常時表示を維持します。

## 口座ごとの準備期間
- 各口座の「期間設定」で、毎月何日分までまとめて準備するかを1〜31で設定します。31は月末として短い月では末日に調整します。今日から次に迎える指定日までが対象です。指定日当日はその日まで、翌日からは次月の指定日までとなります。
- 口座名に応じた固定処理は行いません。既存設定で指定がない口座は従来どおり10日を初期値とし、利用者が変更します。
- 今回の設定例：西武信金10日、楽天銀行27日、三井住友銀行4日。楽天銀行のGalaxy端末代は利用者が登録した定期払いから計算します。本更新で支払いデータは追加しません。
- 対象日までのすべての登録済み予定を合計します。27日・4日・10日以外の引落日も対象です。未処理の過去分も含めます。
- 設定は端末内の暗号化データに保存され、バックアップにも含まれます（mkSettings.accounts[].prepDay）。スキーマ12のまま、旧設定では省略可能です。
- やることリストは口座ごとに1件。期間内の不足総額と、最初に残高が不足する日を表示します。記録された入金・資金移動・引落処理による現在残高の変化で再計算します。将来の給与は先取りしません。
- 2か月先までの内訳は引き続き確認できます。未記録のカード定期払い・将来の買い物・予定収入は含めません。
